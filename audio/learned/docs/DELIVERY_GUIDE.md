# Stage 5/6 — M2 delivery workflow

## What is complete and what remains with M1

| Output | Owner | M2 delivery status |
|---|---|---|
| F_seq `[T,128]` | M2 → M5 | Available in Stage 4 per-sample NPZ files |
| F_learned `[128]` | M2 → M1 | Available in Stage 4 pooled NPZ/CSV files |
| Final F_audio | M1 → M5 | Pending M1's handcrafted/learned representation work |
| Final P_audio `[8]` | M1 → M5 | Pending M1's Level-2 classifier selection |

M2's inference code also returns eight learned-only probabilities for diagnostics or a learned-only baseline. They are explicitly tagged `M2_learned_only_not_final_P_audio`. They must not silently replace the final audio module probabilities.

Stage 6 code now packages a checkpoint, comparison results, all features, configuration/class order, actor splits, portable inference source, reader helpers and a delivery manifest with file hashes. It does not train, reselect an encoder, evaluate test scores or implement M1/M5 fusion.

## Package the current completed experiment (run manually)

From the Mac terminal:

```bash
cd "$HOME/Desktop/prs-group13-multimodal-emotion-recognition/audio/learned" && .venv/bin/python -m ravdess_m2.delivery --features artifacts/stage4_transformer_20261015_194625 --output "deliveries/stage56_$(date +%Y%m%d_%H%M%S)" --zip
```

This validates the existing Stage 4 bundle, checks checkpoint/source compatibility, and creates a **new folder and ZIP**. The original run, checkpoint, raw WAVs and Stage 4 features are preserved. A new experiment must use a new delivery name. No real delivery is generated by merely adding this code; the user runs this command.

Output contents:


`features/` is the portable equivalent of the suggested `audio_features.pt`. Sequence, pooled, sample_id, label, split, actor, length and mask are retained per sample. No duplicate giant tensor file is needed. Package names are engineering choices, not proposal-mandated filenames. Raw audio and all three candidate checkpoints are not copied; only the selected model is packaged.

## Inference on a new audio file (run manually)

From the existing desktop project, replace the input path:

```bash
.venv/bin/python -m ravdess_m2.inference --checkpoint runs/stage3_20261015_194625/transformer/best.pt --audio "/absolute/path/new_audio.wav" --external --output "artifacts/inference/new_audio_$(date +%Y%m%d_%H%M%S).npz"
```

New external recordings get a content-derived `sample_id`, split=`external`, label=`-1`, actor_id=`-1`. Ground-truth emotion is unknown and is not inferred from the model prediction. For official RAVDESS files, omit `--external` and provide `--splits metadata/actor_splits.csv`; the shared ID, actor split and emotion code are read from the original filename and original split assignment. Split hashes are checked.

In an extracted delivery folder, teammates can create a virtual environment, install the supplied requirements and run:

```bash
.venv/bin/python audio_inference.py --audio "/absolute/path/new_audio.wav" --external --output inference/new_audio.npz
```

The packaged checkpoint is used by default. Preprocessing and train-fitted MFCC normalization come from that checkpoint. Inference is frozen, augmentation-free and deterministic on CPU. Output files must be new.

## Repeatable workflow for later experiments

1. Run Stage 3 with a new run directory; wait for all three candidates to complete and the comparison to be written.
2. Run Stage 4 with `--run runs/EXPERIMENT` and `--output artifacts/EXPERIMENT_features`.
3. Run the delivery command with `--features artifacts/EXPERIMENT_features --output deliveries/EXPERIMENT --zip`.
4. Hand the resulting ZIP to M1/M5. Check `stage5_contract.json` for ownership, use sample_id to join, and verify labels/splits/class order before fusion.

Example steps 2 and 3 after an experiment named `EXPERIMENT` finishes:

```bash
.venv/bin/python -m ravdess_m2.feature_export export --run runs/EXPERIMENT --output artifacts/EXPERIMENT_features
.venv/bin/python -m ravdess_m2.delivery --features artifacts/EXPERIMENT_features --output deliveries/EXPERIMENT --zip
```

Do not refit normalization on validation/test data. Keep final test evaluation separate from model/representation selection. The same sample ID alone does not establish audio/video timestamp alignment; M5 must handle sequence lengths/masks and any desired synchronization.

## M5 functional-test outputs: Learned Feature Only

Delivery packaging now also generates a separate `m5_learned_feature_only/` folder. M1 continues using `features/pooled/` without any schema changes. The M5 folder can be handed off independently and includes its own README, class order, metadata and manifest.

Every `m5_learned_feature_only/per_sample/{split}/{sample_id}.npz` contains:

- `F_sequence [T,128]`: exactly the original Stage 4 sequence.
- `F_audio_learned_feature_only [128]`: exactly the Stage 4 pooled vector; no handcrafted concatenation.
- `P_audio_learned_feature_only [8]`: softmax of the selected checkpoint's own frozen MLP applied to that pooled vector.
- `sample_id`, `actor_id`, `split`, `label`, `length`, `padding_mask`, `class_names` and representation role.

For feature/gated/decision fusion, M5 can also read `m5_learned_feature_only/pooled/{train,val,test}.npz` or CSV, which hold matching audio vectors and probability vectors in the same sample-ID order. For cross-attention, use F_sequence and pad the variable-length sequences with True for padding. No video-frame alignment is assumed.

```python
import numpy as np
z = np.load('m5_learned_feature_only/per_sample/train/SAMPLE_ID.npz', allow_pickle=False)
F_sequence = z['F_sequence']
F_audio_learned_feature_only = z['F_audio_learned_feature_only']
P_audio_learned_feature_only = z['P_audio_learned_feature_only']
```

The existing delivery command generates this new folder automatically; no Stage 3 retraining or Stage 4 re-extraction is needed. The original feature files and old deliveries are preserved. Use a new delivery output directory. Packaging calculates frozen classifier probabilities but no task accuracy/F1 or model selection. All three splits are exported separately. Train split probabilities are in-sample, not out-of-fold stacking predictions.

M1's final fused F_audio/P_audio remain pending, while these explicitly named M2 learned-only outputs are ready for M5's functional tests. New-audio inference outputs also include the three explicit keys, retaining the original generic sequence/pooled/probabilities keys for compatibility.
